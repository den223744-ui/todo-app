# AGENTS.md

Правила для AI-агентов (Claude Code, Codex), работающих в этом репозитории.
Полная спецификация продукта — `SPEC.md`. План по этапам — `PLAN.md`. Всегда сверяйся с ними перед работой.

## Команды
```
docker compose up                 # всё приложение
cd backend && uv run pytest       # тесты бэка
cd backend && uv run ruff check . && uv run mypy app
cd frontend && npm run dev
cd frontend && npm run test       # vitest
cd frontend && npm run e2e        # playwright
cd frontend && npm run gen:api    # перегенерировать типы из OpenAPI
```

## Архитектурные правила
- Backend: роутеры тонкие → бизнес-логика в `services/` → модели в `models/`. Каждый запрос скоупится по workspace из cookie; никогда не обращайся к задачам без фильтра по `workspace_id`.
- Схема БД меняется только через Alembic-миграции.
- Frontend: логика без React — в `src/domain/` (чистые функции, `now` передаётся аргументом, никаких `Date.now()` внутри).
- Серверное состояние — только TanStack Query. Zustand — только UI-состояние (выделение, открытые панели, тема).
- Типы API берутся из сгенерированного `src/api/schema.ts`. Ручные DTO запрещены. После изменения схем бэка — `npm run gen:api`.
- Мутации — оптимистичные, с откатом при ошибке.
- Анимации — через Framer Motion; всегда учитывай `prefers-reduced-motion`.

## Стиль кода
- TypeScript strict, без `any`. Python — полные type hints, mypy strict.
- Имена — английские. UI-тексты — русские, вынесены в константы.
- Маленькие компоненты, один компонент — один файл.
- Не добавляй зависимости, не указанные в SPEC.md, без явной причины в описании коммита.

## Процесс
- Работай строго в рамках текущего этапа из PLAN.md. Не делай фичи из будущих этапов.
- Новая логика = новые тесты в том же изменении.
- Перед завершением этапа: линтеры, типы и все тесты зелёные.
- Коммиты — Conventional Commits (`feat:`, `fix:`, `test:`, `refactor:`, `chore:`, `docs:`), маленькие и осмысленные.
- Если требование в спецификации неоднозначно — остановись и спроси, а не додумывай.
