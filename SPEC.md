# Todo App — спецификация

Тестовое задание (fullstack): to-do лист, дизайн на усмотрение кандидата, данные сохраняются после обновления страницы.
Цель — показать инженерный уровень: чистая архитектура, типобезопасный контракт фронт↔бэк, тесты, продуманный UX и плавные анимации. Не количество фич, а качество каждой.

## Стек

**Backend:** Python 3.12, FastAPI, SQLAlchemy 2.0 (async), Alembic, Pydantic v2, pytest + httpx.
БД: SQLite локально и в тестах, PostgreSQL в проде (через `DATABASE_URL`).

**Frontend:** React 18 + TypeScript (strict) + Vite, TanStack Query (серверное состояние, оптимистичные апдейты), Zustand (только UI-состояние), Tailwind CSS, Framer Motion, dnd-kit, cmdk (палитра команд), Vitest, Playwright.
Типы API генерируются из OpenAPI бэкенда (`openapi-typescript`) — руками DTO не пишем.

**Инфра:** монорепо, docker-compose (одна команда поднимает всё), GitHub Actions CI, деплой одним сервисом (FastAPI раздаёт собранный фронт) на Render + Neon Postgres.

## Модель данных

**Workspace:** `id (uuid)`, `created_at`.
Анонимная сессия: при первом запросе бэкенд создаёт workspace и ставит httpOnly-cookie. У каждого посетителя демо свой список без регистрации.

**Task:**

| parent_id | uuid FK nullable | подзадачи, один уровень вложенности |
| list_id | uuid FK nullable | список пользователя; только у задач верхнего уровня, подзадачи следуют за родителем; при удалении списка обнуляется |

## API (`/api`)

| метод | путь | описание |
|---|---|---|
| GET | /tasks | все не удалённые задачи workspace (с подзадачами) |
| POST | /tasks | создать |
| PATCH | /tasks/{id} | частичное обновление (в т.ч. position, completed) |
| DELETE | /tasks/{id} | soft delete |
| POST | /tasks/{id}/restore | восстановить (Undo) |
| GET | /lists | списки workspace по порядку |
| POST | /lists | создать список (409 — имя занято) |
| PATCH | /lists/{id} | переименовать, сменить цвет или порядок |
| DELETE | /lists/{id} | удалить список; его задачи остаются без списка |
| GET | /health | healthcheck |

Ошибки в едином формате `{ "error": { "code", "message" } }`. 404 на чужой workspace (не 403 — не раскрываем существование).
Фильтрация по умным спискам — на клиенте в чистых функциях `domain/` (объём данных мал, зависит от таймзоны пользователя). Решение описано в README.

## Функционал

### База
- Создание, inline-редактирование (двойной клик / Enter, Esc — отмена), выполнение, удаление.
- Приоритет, дата/время, теги, заметки, подзадачи (панель деталей задачи).
- Умные списки в сайдбаре: Входящие, Сегодня, Предстоящие, Просроченные, Выполненные + пользовательские списки (цветная точка, счётчик, «+ Новый список») + список тегов со счётчиками.
  Правила (все списки, кроме «Выполненных», содержат только невыполненные задачи; «сегодня» — по локальной дате пользователя):
  | список | задачи |
  |---|---|
  | Входящие | без даты (`due_date` пуст) |
  | Сегодня | срок сегодня + просроченные; плюс задачи с таким сроком, выполненные сегодня (зачёркнутые, чтобы был виден прогресс дня «N из M выполнено»); группировка по пользовательским спискам, задачи без списка — последней группой |
  | Предстоящие | срок позже сегодня |
  | Просроченные | срок раньше сегодня (сравнение по дате, время не учитывается) |
  | Выполненные | выполненные (`completed_at` заполнен) |

  Пересечение только одно, осознанное: Сегодня ∩ Просроченные — чтобы просроченное не терялось из главного списка дня.
- Пользовательский список показывает свои невыполненные задачи; задача из быстрого ввода в открытом списке попадает в него.
- Подзадачи раскрываются прямо в списке задач (счётчик «1/3»), их можно отмечать там же.
- Экран «Сегодня»: переключатель дня «‹ Сегодня ›» рядом с датой (день в URL `?day=YYYY-MM-DD`); для другого дня показываются задачи с этим сроком, итоги дня и таймлайн этого дня; быстрый ввод ставит задаче выбранный день.
- Таймлайн дня в правой колонке (на широком экране): задачи со временем блоками на сетке часов (пока по 30 минут — длительности у задач нет), пересекающиеся — рядом, линия «сейчас» для сегодня, задачи без времени — списком ниже. Открытая задача занимает место таймлайна.
- Поиск. Активный список/тег/поиск хранятся в URL.
- Пустые состояния для каждого списка, скелетоны загрузки, обработка ошибок сети (тост + откат).

### Фишки
1. **Быстрый ввод на естественном языке** с подсветкой распознанных частей прямо в поле:
   `купить молоко завтра в 18:00 #дом !!` → title, due, tag, priority.
   Грамматика: `сегодня`, `завтра`, `послезавтра`, дни недели (`пн`…`вс`, `понедельник`…), `через N дней`, `дд.мм`, `в ЧЧ:ММ` / `в ЧЧ`, `#тег`, `!` `!!` `!!!`. Чистая функция `parseQuickAdd(input, now)` с полным покрытием тестами.
2. **Оптимистичный UI**: изменения видны мгновенно, при ошибке сервера — откат и тост.
3. **Undo вместо confirm-диалогов**: удаление/выполнение → тост «Отменить» (5 сек) + Ctrl/Cmd+Z.
4. **Drag & drop** сортировка с layout-анимациями, работает и с клавиатуры.
5. **Keyboard-first**: Cmd/Ctrl+K палитра команд; `N` — новая задача, `/` — поиск, `J/K` — навигация, `X` — выполнить, `E` — редактировать, `Backspace` — удалить, `?` — оверлей со всеми хоткеями.
6. **Анимации** (Framer Motion): появление/удаление задач, перестроение списка, чекбокс, переходы между списками. Уважают `prefers-reduced-motion`.
7. **Тёмная/светлая тема** (по системе + переключатель).
8. **Доступность**: семантика, ARIA, видимый фокус, управление фокусом после действий.
9. **Адаптив**: полноценная работа на мобильном (сайдбар → drawer).

### Дизайн
Сдержанный минимализм в духе Linear / Things: нейтральная палитра, один акцентный цвет, аккуратная типографика (Inter), мягкие тени, скругления 8–12px. Без фиолетовых градиентов и эмодзи в UI.

### Вне скоупа (сознательно)
Регистрация/логин, совместные списки, повторяющиеся задачи, уведомления, офлайн-синхронизация. Перечислены в README в разделе «Что дальше».
