# План: 2 дня, 7 этапов

Схема работы на каждом этапе:
1. **Claude Code** реализует этап (промпт ниже) в ветке `stage-N`.
2. **Codex** делает ревью диффа против SPEC.md и AGENTS.md (`/review` в Codex CLI или промпт ревью ниже).
3. Claude Code исправляет замечания → проверка → merge в main.
4. Ты сам руками проверяешь результат в браузере. Ты должен понимать каждый этап — на собеседовании спросят.

Промпт ревью для Codex (одинаковый для всех этапов):
> Сделай код-ревью изменений ветки stage-N относительно main. Сверь с SPEC.md, AGENTS.md и описанием этапа N в PLAN.md. Ищи: баги, нарушения архитектурных правил, непокрытую тестами логику, проблемы безопасности (изоляция workspace), краевые случаи. Ничего не исправляй — выдай список замечаний по приоритету.

## День 1 — фундамент и бэкенд

### Этап 0 — скелет (~1 ч)
> Прочитай SPEC.md и AGENTS.md. Выполни этап 0: создай монорепо по структуре из SPEC.md. Backend: FastAPI-проект на uv, эндпоинт /api/health, ruff, mypy strict, pytest с одним тестом health. Frontend: Vite + React + TS strict, Tailwind, ESLint, Prettier, Vitest, Playwright с одним smoke-тестом. docker-compose.yml, поднимающий оба сервиса. GitHub Actions CI со всеми проверками из Definition of Done. Никакой бизнес-логики.

**Готово, когда:** `docker compose up` работает, CI зелёный.

### Этап 1 — бэкенд (~3 ч)
> Выполни этап 1: модели Workspace и Task по SPEC.md, первая Alembic-миграция, middleware анонимной сессии (httpOnly cookie, создание workspace при первом запросе), сервис задач и все эндпоинты из раздела API, единый формат ошибок. Тесты: каждый эндпоинт, валидация, soft delete + restore, подзадачи, и обязательно — изоляция: workspace A не может прочитать/изменить/удалить задачу workspace B (ожидается 404).

**Готово, когда:** все тесты зелёные, /docs показывает чистый OpenAPI.

### Этап 2 — доменная логика фронта (~2 ч)
> Выполни этап 2: настрой генерацию типов из OpenAPI (`npm run gen:api`), типизированный API-клиент, хуки TanStack Query для всех операций с оптимистичными апдейтами и откатом. В src/domain: parseQuickAdd(input, now) по грамматике из SPEC.md (возвращает поля задачи и диапазоны распознанных токенов для подсветки), фильтры умных списков, сортировка, расчёт position между соседями. Покрой domain тестами на 100% веток, включая краевые случаи (пустой ввод, только теги, «пн» когда сегодня пн, 31.02, время без даты).

**Готово, когда:** vitest зелёный, покрытие domain 100%.

## День 2 — интерфейс, фишки, сдача

### Этап 3 — базовый UI (~3 ч)
> Выполни этап 3: дизайн-токены (цвета светлой/тёмной темы, типографика Inter, отступы) по разделу «Дизайн» в SPEC.md. Лейаут: сайдбар с умными списками и тегами (на мобильном — drawer), список задач, поле быстрого ввода с подсветкой токенов, inline-редактирование, панель деталей (заметки, дата, приоритет, теги, подзадачи), поиск, состояние в URL, пустые состояния, скелетоны, тосты ошибок. Без анимаций и DnD — это следующий этап.

### Этап 4 — анимации, DnD, Undo (~2 ч)
> Выполни этап 4: Framer Motion — появление/удаление задач, layout-анимация перестроения, анимированный чекбокс, переходы между списками; везде учитывай prefers-reduced-motion. dnd-kit сортировка с поддержкой клавиатуры, сохранение position на бэке. Undo: тост «Отменить» на 5 сек после удаления/выполнения + Ctrl/Cmd+Z (restore через API).

### Этап 5 — клавиатура и полировка (~2 ч)
> Выполни этап 5: палитра команд Cmd/Ctrl+K (cmdk), все хоткеи из SPEC.md, оверлей «?», переключатель темы. Аудит доступности: ARIA, видимый фокус, возврат фокуса после действий. Проверь адаптив на 375px.

### Этап 6 — e2e, деплой, README (~2 ч)
> Выполни этап 6: Playwright e2e — создание задачи через быстрый ввод и проверка, что она осталась после перезагрузки; выполнение + Undo; drag & drop; фильтр «Сегодня». Production-сборка: FastAPI раздаёт собранный фронт, Dockerfile, конфиг для Render + Neon Postgres. README: ссылка на демо первой строкой, гифка, запуск, архитектура, раздел «Решения и компромиссы», раздел «AI-assisted разработка» (spec-driven процесс: SPEC → реализация Claude Code → ревью Codex → ручная проверка), «Что дальше».

**Буфер:** ~2 ч на непредвиденное и финальный прогон Lighthouse.
